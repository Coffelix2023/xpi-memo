# [@pi-root-AGENTS.md] 下一轮修复计划：P0 记忆注入闭环修复

## 摘要
本轮只做 **P0**，不碰 Track B、embedding 模型替换、bank 元数据持久化、Markdown 真相源迁移。目标只有一个：把“中文记忆可被自动注入”“用户能看见注入结果”“连续零命中会告警”这三件事补齐，先恢复真实可感知的价值闭环。

## 已定决策
- **注入策略**：采用 **双查询融合**。中文意图查询和英文意图查询分别召回，再合并去重。
- **可见性策略**：注入必须输出一行状态，TUI 和 RPC 共享同一结果文案。
- **告警策略**：新增 `RECALL_ZERO_STREAK（连续零命中告警）`，阈值定为 **10**。
- **医生面板策略**：把现有的 `ROUTING_REJECTED` 证据计数显式展示出来，不改路由语义。

## 要实现的行为
1. **自动注入改为双查询召回**
   - 中文查询：`项目 决策 约束 偏好 未完成工作`
   - 英文查询：`restore project context decisions constraints preferences unfinished work`
   - 两次召回都走现有搜索后端与既有 policy，不新增配置。
   - 合并规则：按同一后端分数取高值，按 `memory id` 去重；没有 `id` 时用稳定内容签名去重。
   - 排序后仍然遵守现有注入上限，不引入新的可调参数。
   - 任何单次查询失败都不阻断另一条；只有两条都失败时才算本次注入失败并返回空结果。

2. **注入结果必须可见**
   - 统一输出状态：`注入 N 条记忆` 或 `无相关记忆`。
   - 这个状态同时进入 TUI 和 RPC 返回路径，不再静默注入。
   - 状态文本与注入结果共用同一份数据，避免两条路径出现不一致。

3. **新增 `RECALL_ZERO_STREAK` 医生状态**
   - 直接从现有 recall / audit 轨迹推导连续零命中次数，不新增持久化表或配置。
   - 规则：任一次 recall 命中 > 0 就清零；连续 10 次零命中就报警。
   - doctor 输出里要能看见当前 streak 值，以及是否已触发告警。

4. **显式展示 `ROUTING_REJECTED`**
   - 把现有的路由拒绝证据计数映射成 doctor 可读状态。
   - 只做展示，不改既有 rejection 记录逻辑。

## 影响范围
- 主要落点：`src/index.ts` 的 recall / inject 路径、`src/doctor.ts` 的报告构建、以及对应测试。
- 不改：工具名、`xpi_memo_recall` / `xpi_memo_forget` 公共签名、数据库布局、bank 语义、L2 设计。

## 验收标准
- 中文记忆在自动注入时可被召回，不再被固定英文模板结构性打空。
- 注入路径在有结果和无结果时都能给出明确状态行。
- 连续 10 次零命中时，doctor 能稳定报出 `RECALL_ZERO_STREAK`。
- `ROUTING_REJECTED` 能在 doctor 面板中被看见。
- 现有 recall / forget / intent 相关回归不退化。

## 测试与验证
- 单元测试：
  - 双查询合并、去重、排序。
  - 零命中 streak 计数、清零、触发阈值。
  - doctor 状态映射（含 `ROUTING_REJECTED`）。
- 集成测试：
  - 写入一条中文 project 记忆，触发自动注入，断言结果非空。
  - 断言注入无结果时仍返回 `无相关记忆`。
- 真实环境冒烟：
  - 按反馈报告里的中文记忆 + 注入场景重跑一遍，确认不再复现“英文模板 0 命中”。
- 最终门禁：`pnpm typecheck`、`pnpm -w run lint`、`pnpm test` 全绿。

## 明确不做
- 不做 Track B / LLM 提取。
- 不换 embedding 模型。
- 不做 bank 元数据持久化。
- 不做 Markdown 真相源迁移。

## 假设
1. 两次召回使用的是同一后端分数尺度，因此可以直接比较并取高值。
2. 现有 doctor / audit 轨迹足够推导零命中 streak，不需要新增持久化状态。
3. 现有 TUI / RPC 返回路径可以共用同一注入状态文本；如果当前实现分叉，就提炼一个共享 helper，而不是复制逻辑。
