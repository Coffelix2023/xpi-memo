# admission-preferences Specification

## Purpose

定义用户可配置的记忆准入偏好及其默认值，让合格的候选默认被记住，而不是默认被排队等待人工放行；同时固定一批不可配置的安全底线。

## Requirements

### Requirement: 可配置的准入偏好集

系统 SHALL 暴露一组准入偏好，决定一个候选是自动写入 T1 还是进入待审队列。偏好集合 MUST 至少覆盖：记忆类型（逐类启用/停用）、最低置信度、证据下限、来源范围、时效窗口。任一偏好未配置时，系统 MUST 使用该偏好的默认值，且默认值 MUST 构成"除硬底线外全部自动准入"的全自动行为。

#### Scenario: 未配置任何偏好时的默认行为

- **WHEN** 用户从未设置任何准入偏好
- **THEN** 系统按默认的全自动偏好判定候选
- **AND** 除硬底线命中的候选外，全部自动写入 T1
- **AND** 候选不因等待人工放行而留在待审队列

#### Scenario: 停用某一记忆类型

- **WHEN** 用户停用某个记忆类型的自动准入
- **THEN** 该类候选进入待审队列
- **AND** 其他类型的自动化行为不受影响

#### Scenario: 置信度阈值

- **WHEN** 候选的置信度低于配置的最低置信度
- **THEN** 候选进入待审队列，不写入 T1
- **AND** 审计记录有界原因，不记录候选正文

#### Scenario: 证据下限

- **WHEN** 用户把证据下限提升为"必须经仓库事实验证"
- **THEN** 仅证据类型为 `verified-repository-fact` 的候选可自动准入
- **AND** `l0-conclusion` 候选进入待审队列

#### Scenario: 来源范围限定为当前项目

- **WHEN** 来源范围偏好限定为当前项目
- **THEN** 目标 bank 不是当前项目 bank 的候选进入待审队列
- **AND** 已写入 T1 的记忆不受影响

#### Scenario: 时效窗口

- **WHEN** 候选的创建时间早于时效窗口
- **THEN** 候选不自动写入 T1
- **AND** 候选按归档契约处理

### Requirement: 硬底线不参与偏好配置

系统 MUST 保持一组不可通过偏好放宽的硬底线。即使偏好为全自动，命中硬底线的候选 MUST 仍被拒绝且 MUST NOT 写入 T1。硬底线 MUST 至少覆盖：内容策略命中的禁止性内容、存在未解冲突的候选、内容为空的候选。

#### Scenario: 全自动偏好仍拒绝禁止性内容

- **WHEN** 偏好为全自动，且候选内容命中内容策略
- **THEN** 候选被拒绝，不写入 T1
- **AND** 任何偏好取值都无法放行该候选

#### Scenario: 全自动偏好仍拒绝未解冲突

- **WHEN** 候选携带未解决的冲突状态
- **THEN** 候选不自动写入 T1
- **AND** 候选按冲突处理路径进入人工确认

### Requirement: 偏好解析优先级与失败回退

偏好解析 MUST 按固定优先级进行：全局 kill switch 优先，其次是显式设置的环境变量，其次是配置文件值，最后是内置默认值。非法或不可识别的偏好取值 MUST 被忽略并回退到该偏好的默认值；系统 MUST 记录被忽略的配置键，MUST NOT 因单个非法键而拒绝整份配置。

#### Scenario: kill switch 优先于一切

- **WHEN** 全局 kill switch 被设置为关闭
- **THEN** 所有自动准入路径被禁用
- **AND** 偏好与环境变量的取值都不使其恢复

#### Scenario: 环境变量覆盖配置文件

- **WHEN** 同一偏好同时由环境变量与配置文件给出
- **THEN** 系统使用环境变量值
- **AND** 配置文件中的该键不影响结果

#### Scenario: 非法取值回退默认

- **WHEN** 配置文件中某个偏好取值非法
- **THEN** 该偏好回退到内置默认值
- **AND** 其余合法键照常生效
- **AND** 被忽略的键可从配置解析结果中读取
