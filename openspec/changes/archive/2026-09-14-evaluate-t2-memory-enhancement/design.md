## Context

`xpi-memo` 已有 L0 事件链、T1 候选治理、Mnemosyne/ripgrep/qmd 搜索回退和 Markdown 投影。候选工具的完整生命周期与 xpi-memo 重叠，因此本设计只允许派生读取、离线评估和可选 adapter，不引入第二个事实写入者。

## Goals / Non-Goals

**Goals:**

- 用统一的真实中文数据集比较当前 baseline 与候选能力。
- 同时评估无 embedding、本地 embedding、云端 embedding 三档。
- 验证用户画像、工作流、项目知识、技能四类进化是否有证据支持。
- 设计轻量证据图作为可回滚的可选重排信号。
- 定义流光状态提示、失败降级和 T2 adapter 隔离边界。

**Non-Goals:**

- 当前不安装或接入四个候选项目。
- 当前不接入 `ai-memory`，不建设跨设备共享服务。
- 不把图谱作为 T1 数据库，不替换原始 L0 证据。
- 不在热路径调用 LLM，不改变现有 Mnemosyne bank 或 L0 schema。

## Decisions

1. **T2 采用派生增强层，而非并列记忆库。**
   这样保留现有治理、删除、审计和回滚边界。并列写入会造成重复捕获、冲突合并和双重事实权威；作为外部 MCP 服务也会绕开现有 provenance。

2. **评估先静态筛选，再做真实中文场景。**
   静态阶段检查本地运行、许可证、中文能力、原文保留、可关闭云端模型、精确删除和 adapter 边界；只有通过者进入统一运行评测。当前不安装候选，避免把环境接入误当成架构决策。

3. **召回采用 baseline 保底、T2 低权重融合。**
   T2 结果必须标准化并带来源证据；T2 失败时直接回退现有配置链。T2 不得单独决定自动注入，避免派生错误压过 T1。

4. **图谱只保存证据关系。**
   第一阶段只考虑 `supports`、`contradicts`、`supersedes`、`temporal-next` 和 `related` 等有限边类型；关系必须指向原始记忆或 L0 事件。完整实体图、代码图和远程图数据库留到实证后。

5. **进化放在离线生命周期。**
   提案生成只在 shutdown、compact 或显式 sleep 执行，并沿用现有 extraction budget、外部安全边界和 candidate lifecycle。普通 recall 不增加模型调用。

6. **状态提示与治理分离。**
   状态提示只传达动作与结果，不携带正文；流光、灰度、不显示只影响可见性，不改变存储和候选决策。需要用户判断时复用已有候选确认界面。

## Risks / Trade-offs

- [候选中文质量无法从 README 推断] → 使用固定中文场景、相同 query、相同 top-k 和人工可复核证据进行比较。
- [图谱抽取引入错误关系] → 保留原文和来源，限制边类型，图谱只做低权重重排，失败时禁用。
- [云端 embedding 泄露敏感内容] → 复用外发安全边界，提供关闭和本地模式，测试中记录数据传输边界。
- [状态提示过多打扰 Pi] → 只显示短暂结果，不弹咨询框；仅候选确认可打断。
- [额外索引导致维护成本] → T2 默认关闭，索引可重建、可删除，T1/L0 不依赖 T2。

## Migration Plan

1. 先只提交评估矩阵、中文场景和结果格式，不改运行时。
2. 若候选通过硬门槛，再实现 disabled-by-default 的只读 adapter。
3. 以当前 baseline 做回归，开启 adapter 后进行 A/B 评测。
4. 失败时关闭配置并删除派生索引；T1 banks、L0、审计和 Markdown 投影无需迁移。
5. `ai-memory` 保持未接入状态，未来若需要共享能力，另开独立变更评估只读 handoff/共享投影。
