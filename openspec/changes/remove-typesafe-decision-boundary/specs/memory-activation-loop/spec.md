## REMOVED Requirements

### Requirement: Recall 精排必须门控、有界且可完全旁路

**Reason**: 该需求允许在粗排之后调用一次外部精排，但精排按定义只能重排已入选的候选、不能增删结果。仓库内记录的头号动机场景是"召回头部被常驻记忆挤占、目标记忆落榜"——目标不在选择集内时，重排的收益恒为零。同一症状在本仓库已有零外发、零成本的本地杠杆：既有反馈权重（`wrong −0.25`、`irrelevant −0.15`、`correction −0.5`）量级远高于本需求的门控阈值 0.05。因此这条需求既治不了记录在案的病，又为它保留了一条外部调用路径。

**Migration**: 无替代。recall 排序回到纯本地路径：粗排分数叠加既有反馈调整，不再有门控阈值、精排调用与门控计数。为精排门控服务的 `headGap` 诊断字段一并移除，因为它没有其他消费方。

### Requirement: 重复 prompt 必须经确定性计数与稳定性判定才产生候选

**Reason**: 第二阶段的稳定性判定依赖被移除的决策 runner，而第一阶段的同义重复计数按空格分词后再算 Jaccard 相似度（阈值 0.8），对无空格的中文 prompt 而言整句退化为单一 token——中文场景下"同义重复"实际只能匹配近乎逐字相同的重复，而这恰恰是设计里想排除的挫败型重复。同时该需求声明的"跨会话才近似稳定"在实现中并未进入判定门槛。判据与意图不一致，且没有实测证明它能产出被采纳的候选。

**Migration**: 无替代。重复的 prompt 不再自动产生任何候选；记忆捕获回到既有的显式意图捕获与门控离线提取路径。已产生的历史候选与 L0 事件不受影响，无需迁移。
